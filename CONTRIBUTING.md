# Руководство по внесению вклада в DocCompare

Спасибо за интерес к улучшению DocCompare! 🎉

## Как внести вклад

### Сообщить об ошибке

1. Проверьте, не была ли уже создана подобная issue
2. Создайте новую issue с подробным описанием:
   - Версия Python
   - Операционная система
   - Шаги для воспроизведения
   - Ожидаемое и фактическое поведение
   - Логи или скриншоты

### Предложить новую функцию

1. Создайте issue с описанием:
   - Какую проблему решает новая функция
   - Как она должна работать
   - Примеры использования

### Внести код

1. **Fork репозитория**

2. **Клонировать и настроить**
   ```bash
   git clone https://github.com/your-username/DocCompare.git
   cd DocCompare
   git checkout -b feature/your-feature-name
   ```

3. **Настроить окружение**
   ```bash
   python -m venv venv
   source venv/bin/activate
   pip install -r requirements.txt
   make docker-up
   ```

4. **Внести изменения**
   - Следуйте стилю кода (используйте `make format`)
   - Добавьте тесты для новой функциональности
   - Обновите документацию при необходимости

5. **Запустить тесты и линтинг**
   ```bash
   make test
   make lint
   make format
   ```

6. **Commit изменений**
   ```bash
   git add .
   git commit -m "feat: добавлена поддержка формата RTF"
   ```
   
   Используйте conventional commits:
   - `feat:` - новая функция
   - `fix:` - исправление ошибки
   - `docs:` - изменения в документации
   - `refactor:` - рефакторинг кода
   - `test:` - добавление тестов
   - `chore:` - обновление зависимостей и т.п.

7. **Push и создание Pull Request**
   ```bash
   git push origin feature/your-feature-name
   ```
   
   Создайте Pull Request на GitHub с описанием:
   - Что изменено
   - Почему это нужно
   - Как протестировано

## Стандарты кода

- **Python**: PEP 8, black formatter
- **Типизация**: используйте type hints
- **Docstrings**: Google style
- **Тесты**: pytest, минимум 80% покрытия для новых функций

## Структура коммитов

```
type(scope): subject

body

footer
```

Пример:
```
feat(llm): добавлена поддержка Azure OpenAI

Реализована возможность использовать Azure OpenAI вместо OpenAI API.
Добавлены новые переменные окружения для конфигурации.

Closes #42
```

## Процесс review

1. Автоматические проверки (CI/CD) должны пройти успешно
2. Код будет проверен мантейнером
3. При необходимости будут запрошены изменения
4. После одобрения PR будет смержен в main
